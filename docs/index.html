The whole thing in three steps

1 Record & save a copy

Record a 5-minute clip on the recorder with a phone clock in view. Export that same clip to a USB stick. This copy is the answer sheet.

2 Delete & copy the disk

Delete the recording in the recorder's menu and switch it off straight away. Take the disk out and save it as one big file (a disk image).

3 Run the kit, send the report

Run one command. It writes a report card. Send us the small result folder, not the disk image.

Detailed steps

What you needThe recorder (any brand) and its hard disk · a camera or any video source · a PC with Python 3.11+ and FFmpeg · a USB-SATA adapter or dock (a hardware write blocker is better) · a second drive with room for the disk image · a phone or clock to film
1. RecordSet the recorder's clock and note the time zone. Record about 5 minutes with a clock or stopwatch visible to the camera.
2. Export the clipWith the recorder's own menu or player, export that same clip to a USB stick. Keep it as clip.mp4 (or whatever the recorder produces).
3. Image before (optional)Power off, remove the disk, connect it through the dock or write blocker, and create a raw image with FTK Imager (File → Create Disk Image → Physical Drive → Raw (dd)) called original.dd. If Windows offers to format or initialise the disk, choose Cancel.
4. DeletePut the disk back. Delete the recording through the recorder's menu (don't format) and switch the recorder off immediately.
5. Image afterRemove the disk again and image it the same way: deleted.dd.
6. Install the kitUnzip the download. Windows: double-click install_kit.bat. Linux/macOS: ./install_kit.sh. (Once only.)
7. Fill in the notesOpen validation_notes_template.json and write the recorder's brand, model, firmware and what you did.
8. Runrun_kit.bat --after deleted.dd --clip clip.mp4 --before original.dd --notes validation_notes_template.json --out result
(Linux/macOS: ./run_kit.sh …. Leave out --before if you skipped step 3.)
9. Send backThe folder result: validation_report.pdf, validation_report.md, results.json.

Privacy & safety

  • ✔ Nothing is uploaded: it runs offline on your computer.
  • ✔ The disk images are opened read-only and checked with a fingerprint (SHA-256) before and after, so you can prove they were not changed.
  • ✔ Use a spare test disk if you can, so private footage stays private.
  • ✘ Do not send the disk images unless you choose to; the report folder is enough.

What the report tells you

  • One-line verdict: matches / partly recovered / nothing found.
  • How many frames of your clip came back, whether they are correct and in the right order.
  • Where on the disk the recovered bytes came from (if you gave the "before" image).
  • What was not measured. It never guesses a number.

Questions

Does it work for my brand?

Dahua, CP Plus, Hikvision, Prama, Hanwha Vision (Samsung), and WFS (Xiongmai) have dedicated storage and timestamp decoders. For any other brand the kit tries a generic H.264/H.265 byte carver.

How big are the files?

A disk image is as large as the disk (a 500 GB disk gives a 500 GB file), so a small or fresh disk is easiest. The kit itself is under 1 MB and the report folder is small.

The report says "nothing found". Did I do something wrong?

Not necessarily: that is a real finding. Either the footage was zeroed out or our tool does not yet understand that specific recorder firmware. Send the report anyway.

Is one result enough to say the tool works?

No. One run measures one recorder in one situation. It is empirical evidence, not a general recovery rate.

How do I check the download is genuine?

Compare the SHA-256 above with the file's hash (Windows: certutil -hashfile sih-validation-kit.zip SHA256). The source code is public.
